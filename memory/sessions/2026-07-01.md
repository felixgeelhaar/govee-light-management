## Decisions Made

- Discovery must never be stricter than the Connect check — added a lenient `/user/devices` raw-fetch fallback in `CloudTransport.discoverDevices()` that runs when the strict client throws or returns zero, skipping only malformed devices. Reasoning: Connect only checks HTTP status, so it "succeeds" while the client's whole-batch Zod parse (`GoveeDeviceRepository.findAll`) throws on one bad device and `canControl()` can filter all → users saw "no devices found" with a valid key (#304).
- Preserve the primary discovery result when the fallback yields no lights (keeps `unsupportedDevices` cloud-group entries for the PI). Reasoning: Copilot review caught that returning `{lights:[]}` on fallback failure would drop already-discovered group entries.
- CI tests on a **single** Node version = **20**, not a matrix. Reasoning: Stream Deck runs plugins on the runtime pinned in `manifest.Nodejs.Version`; testing other versions adds no signal. Chose 20 (not 24) because `@elgato/cli@1.7.4` — latest — still rejects `Nodejs.Version:"24"` with a schema `const` error, so 24 (though in Elgato docs) is not yet packable. Dropped the `Test (Node 22)` required status check from branch protection.
- Released the #304 fix as patch **v2.7.11** (runtime unchanged, so no minor bump).

## What Went Wrong

- Repeated merge stalls: `main` branch protection is `strict:true` + `required_conversation_resolution` on. Each merge put the next PR BEHIND (forcing full CI re-runs, serialized), and unresolved Copilot review threads showed as an unexplained `BLOCKED` state even with all checks green. Cost several diagnosis rounds. Fix each time: `gh pr update-branch`, and resolve the Copilot thread via GraphQL `resolveReviewThread`.
- Two throwaway watcher scripts failed on zsh (`status` is a read-only variable) — use a non-reserved var name in poll loops.
- `json.dump` reformatted the entire `manifest.json` (97-line noise diff) when I only needed one field — used a surgical `perl` edit instead.
