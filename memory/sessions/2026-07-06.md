## Decisions Made

- **#311 fix — attempt control regardless of the unreliable `online` flag.** Devices (H619A string lights) were discovered but not controllable: the plugin threw "X is offline and cannot be controlled" without sending the command. Root cause: `Light.canBeControlled()` returns `_state.isOnline`, set directly from the Govee cloud API's `online` field in `GoveeLightRepository.getLightState()` (line ~381) — a field known to be unreliable (reports reachable devices offline), the same cloud-API flakiness class as #304. Chose the lenient approach (attempt + surface real error) over trust-but-verify; kept `isOnline`/`getControllableLights()` for display/power-glyph/offline-recovery.
- **Full sweep after the core fix** (user: "full sweep to see if we fall into this trap elsewhere"). The core control path (`ActionServices.controlTarget → LightControlService.controlGroup`) covers power/brightness/color/temp, but 16 OTHER control-dispatch loops bypass it with `for (light of group.getControllableLights())` — scene/snapshot/recall/toggle/segment/sequence/effect/solid-color-prep. Chose **option (b)**: repoint each control-dispatch loop + 8 representative-pick `[0]` sites to `group.lights`, leaving the ~20 display/recovery uses of `getControllableLights()` (which legitimately need the flag) untouched — far lower blast radius than redefining `canBeControlled()`. Also fixed the post-command cache-remember loop (ActionServices ~1251) to remember all commanded members. All in #312.
- **CI-flakiness investigation** (user asked, pre-merge). Only real vector: `test/integration/resilience/CircuitBreaker.test.ts` uses real `setTimeout(1100)` vs `recoveryTimeout:1000` (100ms margin ×4-5). Everything else is non-fatal (Security Audit + coverctl coverage gate are both `continue-on-error`/`|| true`) or guarded (E2E `retries:2`) or deterministic (CodeQL; the other "timing" suites only use `Date.now()` for data). Empirically 0/35 stress runs flaked. Converted CircuitBreaker to fake timers anyway (mirrors SchedulerEngine) → #313; test work dropped from ~5.5s real sleeps to 6ms.
- **Released v2.7.13** (#314): bumped package.json + package-lock.json + manifest.json (2.7.13.0) + CHANGELOG; tag `v2.7.13` → release.yml packed + published the `.streamDeckPlugin`.

## What Went Wrong

(2) The "Code Quality & Coverage" required check is effectively a rubber stamp on coverage (non-fatal) — a latent gap, not a flake.
